# 면담 보고서 무한 코칭 설계

## 목표

면담 보고서 루브릭은 글의 완성을 판정하는 종료 조건이 아니라, 매 라운드 학생에게 가장 유용한 다음 수정 행동 두 가지를 고르는 진단 도구로 사용한다. 학생 코칭에는 종료 상태가 없으며 도달도는 루브릭 충족률이 아니라 누적 수정 노력으로 계산한다.

## 고정 규칙

- 목표 분량을 채운 뒤 받는 첫 코칭의 도달도는 글의 루브릭 상태와 무관하게 정확히 40%다.
- 두 번째 코칭부터 직전 수정미션의 `done` 하나당 10%를 더한다.
- `partial`과 `not-done`은 도달도를 올리지 않는다.
- 도달도는 감소하지 않고 상한도 없다. 100%, 140%, 200%, 260%를 넘어 계속 누적할 수 있다.
- 의미 있는 글에는 매 라운드 수정미션을 정확히 두 개 제공한다.
- 모든 루브릭 기준이 `met`이어도 더 명확한 전달, 더 구체적인 정보, 더 나은 구성처럼 현재 글을 한 단계 개선할 미션 두 개를 제공한다.
- `complete`, `완성`, `완벽`, `모든 기준 충족으로 종료`라는 제품 상태를 사용하지 않는다.
- 글을 전혀 고치지 않았다면 직전 미션은 모두 `not-done`이고 도달도는 유지된다.

## 루브릭과 미션 선택

루브릭 판정은 매 라운드 계속 수행하고 기록한다. `unmet`과 `partial` 기준이 있으면 기존 우선순위에 따라 가장 중요한 두 수정 대상을 고른다. 수정할 미충족 기준이 두 개보다 적으면 이미 `met`인 기준 중 현재 글에서 더 발전시킬 여지가 큰 기준을 채워 항상 서로 다른 대상 두 개를 만든다.

Gemini는 선택된 대상마다 학생 글에 맞춘 새 미션을 생성한다. 제목은 `~하기` 형태이고, 설명에는 학생이 손댈 위치와 실행 동작 및 방법이 있어야 한다. 막연한 조언, 복사 가능한 모범 문장, 학생 글이나 면담에 없는 사실은 허용하지 않는다.

## 데이터 흐름

첫 라운드는 `previousMissions`가 없으므로 도달도를 40으로 저장한다. 이후 라운드는 Gemini가 직전 미션을 `done`, `partial`, `not-done`으로 판정하고, 서버가 `done` 개수만 세어 기존 `computeNextAttainment`로 새 도달도를 계산한다.

루브릭 기반 백분율은 학생 도달도 계산에 사용하지 않는다. 분석·교사 기록을 위해 루브릭 판정 자체는 라운드에 보존할 수 있지만 학생의 누적 도달도와 분리한다.

## 화면

도달도 숫자는 상한 없이 표시한다. 막대의 시각적 너비만 100%에서 끝날 수 있지만 100% 이상을 완성이나 종료로 표현하지 않는다. 100% 이상에서도 성장과 다음 도전을 나타내는 문구를 사용한다.

피드백 영역은 항상 잘한 점과 수정미션 두 개를 표시한다. 루브릭 완료 축하 상자와 `complete` 분기는 제거한다.

## 오류와 방어

- 의미 없는 글과 욕설 검토 흐름은 기존 동작을 유지한다.
- 직전 미션 ID가 빠지거나 중복되거나 판정 개수가 다르면 Gemini 응답을 거부하고 재시도한다.
- 의미 있는 글인데 미션이 두 개가 아니면 응답을 거부하고 재시도한다.
- 저장 실패 시 도달도와 라운드를 부분 갱신하지 않는다.

## 종료 조건

- 첫 코칭 40%, 이후 `done` 하나당 +10%, 나머지 상태 +0%가 자동 테스트로 증명된다.
- 12개 라운드에서 두 미션을 계속 달성해 260%까지 누적되는 테스트가 통과한다.
- 모든 루브릭이 `met`인 여러 글에서도 매번 미션 두 개가 생성되고 종료 상태가 발생하지 않는다.
- 실제 Gemini 개발셋 3회 반복에서 스키마 100%, 미션 두 개 생성 100%, 종료 상태 0건, 미션 위반 0건을 만족한다.
- 루브릭 판정 일치율은 개발셋 90% 이상, 검증셋 85% 이상이며 허위 충족과 논리 모순은 0건이다.
- 로컬 다회차 흐름, 새로고침 후 저장 상태, 100% 초과 표시를 확인한다.
- 전체 테스트, 린트, 프로덕션 빌드가 통과하고 다른 장르의 기존 코칭에 회귀가 없다.
