## 채점기준 코칭 — 단원 구동식

원래 "면담 보고서 한 장르만" 파일럿이었다. 2026-08-30~09-01에 **단원이 성취기준과 채점기준을 직접 들고, AI 채점기준이 있는 단원이면 어느 단원이든 같은 파이프라인을 타는** 구조가 됐다. 상세는 [CHANGELOG](CHANGELOG.md) 맨 아래 세 항목.

| 단원 | 성취기준 | AI / 교사·AI / 교사 | 스모크 의도 일치 |
|---|---|---|---|
| 1단원 줄거리 간추리기 | 아직 없음 | 채점기준 없음 | — |
| 2단원 면담 보고서 쓰기 | 6국01-04 | 4 / 0 / 2 | **12/12** (대조군) |
| 5단원 기사문 작성하기 | 6국03-04 | 2 / 3 / 1 | 12/15 |
| 매체 단원 매체 성찰 보고서 | 6국06-04, 6국03-06 | 3 / 0 / 2 | 8/9 |
| 6단원 이야기 바꾸어 쓰기 | 6국05-05 | 3 / 0 / 3 | **5/9** |
| 보완단원 기행문 쓰기 | 6국03-03, 6국03-05 | 5 / 1 / 2 | 15/18 |

**보완단원**(2026-09-01 추가)은 교육과정 성취기준에는 있는데 **교과서에 단원이 없는** 자리를 메운다. 교육과정이 부르는 이름 그대로이고, 매체 단원처럼 번호가 없어 `unitLabel`이 번호 자리에 들어간다. 두 번째 성취기준(`6국03-05` 쓰기 과정·고쳐쓰기)은 항목이 전부 교사 몫이라 그 청크가 통째로 AI 밖에 남는다.

**핵심 규칙 — 코칭에는 끝이 없다** (안 바뀜)

| 항목 | 규칙 |
|---|---|
| 첫 코칭 도달도 | 글 상태와 무관하게 **40%** |
| 이후 도달도 | 직전 미션 `done` 하나당 **+10%** |
| 상한 | **없음.** 막대 너비만 100%에서 멈추고 숫자는 계속 올라감 |
| 매 라운드 미션 | 항상 **정확히 2개** |
| 완료 상태 | **없음.** `complete`/"완성"/"완벽"을 쓰지 않음 |

**평가 주체 세 가지** — `ai`(디노가 판정, 보드에 표시) / `teacher-ai-feedback`(선생님이 판정, AI는 조언만, 보드엔 `—`) / `teacher`(AI가 존재 자체를 모름). `getAiRubrics`와 `showsAiVerdict`가 두 관문이다.

## 교실에서 나온 여섯 가지 (2026-09-08) — 배포 전 스모크 필요

`bdb8201`, `cb31c74`. 상세는 [CHANGELOG](CHANGELOG.md) 맨 아래.

| 무엇이 문제였나 | 어떻게 고쳤나 |
|---|---|
| 글이 그대론데 AI 판정이 빠졌다 | `lib/assessmentRatchet.js` — 판정을 한 방향으로 잠갔다. 원 판정은 `round.rawAssessments`에 남는다 |
| 이미 쓴 걸 또 쓰라고 했다 | 채점기준으로 시킬 게 없으면 `POLISH_TARGETS`(맞춤법·문장 다듬기)로 넘어간다. `refinementSeed` 삭제 |
| 스페이스만 눌러도 통과 / 정상 학생은 차단 | 공백뿐인 긴 글을 잡고, `MAX_WHITESPACE_RUN`(30)을 주력으로, 비율은 공백을 접은 뒤 잰다 |
| 무의미한 글이 회차를 먹었다 | `discardNonsenseRound` — DB를 안 건드린다. 목표 글자 수 게이트가 풀리던 버그도 함께 해소 |
| 최신 회차를 보려면 끝까지 밀어야 했다 | 최신 한 장이 맨 왼쪽, 가름줄 뒤로 1차부터. 카드는 기준 → 글 → 미션, 미션은 제목만 |

**핵심 규칙 하나가 바뀌었다** — 채점기준 판정은 이제 **내려가지 않는다.** 보드의 `▼`는 개편 전 라운드에만 남는다.

**글다듬기 미션에서만 예시 표현을 허용한다.** 바르게 쓴 말을 안 보여 주면 맞춤법 교정 지시가 성립하지 않기 때문이고, 그래서 인용 치환·예시 금지 검사가 이 미션만 비껴간다.

## 다음 할 일

### 1. ⚠️ 스모크를 돌리고 배포한다 — 이번 작업이 아직 프로덕션에 안 나갔다

`bdb8201`, `cb31c74`가 **로컬 커밋까지만 되어 있다.** 미션 프롬프트에 글다듬기 블록이 새로 붙었으므로 `npm run smoke -- --runs 3`을 한 번 돌려 보고 push해야 한다(Gemini 실호출 · 비용). 볼 것은 위 검증 상태에 적어 두었다. 스모크가 깨끗하면 `git push origin master`가 곧 배포다.

### 2. 6단원 `cause-and-effect` / `story-flow`를 어떻게 할지 정한다

교육과정 자료에 **"AI : 생각해봐야함"**으로 적힌 그 두 항목이, 스모크에서 정확히 안 맞는 두 항목이다(6단원 5/9 중 4건이 이 둘). **판정은 3회 내내 흔들리지 않았고**, 모델 쪽 읽기도 대체로 말이 된다 — 어긋난 건 오히려 제가 지어낸 정답 쪽일 수 있다.

지금은 `ai`로 두었다. 실제 학생 글로 몇 편 돌려 보고 선생님이 판단하는 게 맞다. 내리기로 하면 `lib/curriculum.js`에서 `evaluator`를 `teacher`로 한 줄씩 고치면 되고, `getAiRubrics`가 알아서 프롬프트·스키마·미션 후보에서 빼 준다.

**보완단원에도 같은 종류의 어긋남이 3건 있다**(15/18). `trip-reason`이 두 케이스에서 `unmet` 대신 `partial`로 나왔는데 — "현장체험학습을 갔다", "할머니 댁에 갔다"를 떠난 까닭으로 읽은 것이라 모델 쪽이 오히려 그럴듯하다 — `overall-feeling`은 반대로 `partial` 대신 `unmet`으로 엄격했다. **셋 다 3회 내내 흔들리지 않았다.** 정답을 지어낸 쪽이 틀렸을 가능성이 커서 실제 학생 글을 보기 전까지 손대지 않는다. 관건이던 **여정/견문 구분은 갈라내는 데 성공했다**(장소만 나열한 글에서 `itinerary` met · `observation` partial).

### 3. 실제 학생 글로 다시 돌린다

`evals/smoke/*.json`의 글도 의도한 판정도 전부 이 저장소가 지어낸 것이다. **"모델이 글을 의도대로 읽었다"까지만 말한다.** 실제 학생 글(맞춤법·문장이 서툰)에서 판정이 어떻게 나오는지가 진짜 물음이다.

### 4. 평가 픽스처 재라벨링 → 라이브 평가

`evals/interview-report/*.json`이 `purpose`/`interviewee`/`opening`/`body`/`closing` 등 **없어진 기준**으로 라벨링돼 있다. 4개 기준으로 다시 매겨야 `npm run eval`이 의미를 갖는다. **⚠️ Gemini 실호출이라 비용 발생.**

## 나중 후보

- 채점기준표에 **AI 판단 근거** 붙이기 — 스키마에 근거 필드가 없어 뺐다
- **인용 치환이 만든 어색한 문장** — 모델이 학생 글에 없는 말을 인용하면 "학생 글의 관련 내용"으로 바꿔 넣는데, 보완단원 스모크에서 *"학생 글의 관련 내용은 생각과 실제 본 모습을 비교하며…"* 같은 읽기 힘든 문장이 나왔다. 치환은 의도대로 동작했고 학생에게 틀린 말이 나가진 않았다. 같은 케이스에서 **미션 재시도가 4회**까지 갔다(한계 5회)
- **Gemini 호출 실패 원인이 로그에 안 남는다** — `lib/coaching.js`의 `catch {}`가 에러를 삼키고 502로 바꾼다
- **목표 글자 수는 1회차에만 검사한다** — 2회차부터 조건이 없어 30자로 지워도 라운드가 쌓인다(의도된 설계다. 무의미 글로 게이트가 영영 풀리던 버그는 2026-09-08에 고쳤다)
- **보드 화살표 연타** — 애니메이션 중 재클릭이 누적 안 됨. 2026-08-30에 안 고치기로 함
- Phase 2 잔여 — 참여 학생 목록 정렬/검색
- 가드의 **자모** 임계값을 실제 학생 글 샘플로 튜닝 — 공백 쪽은 2026-09-08에 고쳤다
- **개편 이전 라운드는 AI 판정 칸이 빈다** — 옛 `criterionId`. 마이그레이션 안 하기로 함
