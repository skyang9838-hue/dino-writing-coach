## 채점기준 코칭 — 이제 단원 구동식이다

원래 "면담 보고서 한 장르만 루브릭 코칭" 파일럿이었다. 2026-08-30~31 이틀에 걸쳐 **단원이 성취기준과 채점기준을 직접 들고, AI 채점기준이 있는 단원이면 어느 단원이든 같은 파이프라인을 타는** 구조로 바뀌었다. 상세는 [CHANGELOG](CHANGELOG.md) 맨 아래 두 항목.

| 단원 | 성취기준 | AI / 교사·AI / 교사 | Gemini 실호출 |
|---|---|---|---|
| 1단원 줄거리 간추리기 | 아직 없음 | 채점기준 없음 | — |
| 2단원 면담 보고서 쓰기 | 6국01-04 | 4 / 0 / 2 | ✅ 실제 코칭 7라운드 |
| 3단원 매체 성찰 보고서 | 6국06-04, 6국03-06 | 3 / 0 / 2 | ❌ **한 번도 안 태워봄** |
| 5단원 기사문 작성하기 | 6국03-04 | 2 / 3 / 1 | ❌ **한 번도 안 태워봄** |
| 6단원 이야기 바꾸어 쓰기 | 6국05-05 | 3 / 0 / 3 | ❌ **한 번도 안 태워봄** |

**핵심 규칙 — 코칭에는 끝이 없다** (안 바뀜)

| 항목 | 규칙 |
|---|---|
| 첫 코칭 도달도 | 글 상태와 무관하게 **40%** |
| 이후 도달도 | 직전 미션 `done` 하나당 **+10%** |
| 상한 | **없음.** 막대 너비만 100%에서 멈추고 숫자는 계속 올라감 |
| 매 라운드 미션 | 항상 **정확히 2개** |
| 완료 상태 | **없음.** `complete`/"완성"/"완벽"을 쓰지 않음 |

**평가 주체 세 가지** — `ai`(디노가 판정, 보드에 표시) / `teacher-ai-feedback`(선생님이 판정, AI는 조언만, 보드엔 `—`) / `teacher`(AI가 존재 자체를 모름). `getAiRubrics`와 `showsAiVerdict`가 두 관문이다.

## 다음 할 일

### 1. 평가 픽스처를 새 기준으로 다시 라벨링 → 라이브 평가

`evals/interview-report/*.json`이 `purpose`/`interviewee`/`opening`/`body`/`closing` 등 **없어진 기준**으로 라벨링돼 있다. `purpose-and-target` / `preparation` / `learned-facts` / `reflection` 4개로 다시 매기고 나서야 `npm run eval`이 의미를 갖는다.

그다음 `npm run eval -- --set dev --runs 3` → 판정 일치율 90%+ 등 게이트. **⚠️ Gemini 실호출이라 비용 발생. 돌리기 전에 사용자 확인.**

### 2. 새 단원 3개를 실제로 태워보기

3·5·6단원은 데이터와 프롬프트 생성까지만 확인됐다. 판정이 쓸 만한지는 아무도 모른다. 특히:

- 6단원 `cause-and-effect` / `story-flow` — 자료에 **"AI : 생각해봐야함"**으로 적힌 항목. 일단 `ai`로 넣었고, 판정이 흔들리면 `evaluator` 한 줄만 `teacher`로 내리면 된다
- 5단원 `five-w-one-h`는 "전문만 보고 판정"이라는 규칙이 실제로 지켜지는지

### 3. 사용자에게 확인받을 것

- **3단원 번호** — 자료에 "매체단원"으로만 적혀 있어 3으로 가정했다
- **1단원 줄거리 간추리기** — 성취기준·채점기준 자료가 아직 없다. 장르 `줄거리 요약`, 권장 400자, 아이콘 📜도 가정값
- `국어 2학기 교육과정 분석하기.txt`가 저장소 루트에 **untracked로 남아 있다** — 커밋할지 지울지

### 4. 변화 화살표(`↑▼`)에 섞인 판정 잡음

무변경 재코칭의 판정 뒤집힘은 `56ddb14`로 막았지만, 글이 실제로 바뀐 라운드의 화살표에도 같은 잡음이 섞여 있을 수 있고 아직 측정도 안 했다.
